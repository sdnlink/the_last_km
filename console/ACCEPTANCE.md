| 使用需求 | 交付行为 | 验证 |
| --- | --- | --- |

| 新要求确实发给 AI | 新版监督器在调用前把全部补充要求加入工人和审查器提示词；进程实际启动后写发送回执，有效轮次结果返回后写响应回执 | 真实本地子进程测试核对双方提示词；浏览器提交后观察到对应新进展与回执 |

| 手机可用 | 看板和交互内容在窄屏纵向排列 | 390px 浏览器验证无横向溢出 |

验证结果：完整离线回归 **325 项通过**；桌面和手机浏览器检查通过，无 JavaScript 错误。验证使用本地模拟执行器，没有调用付费模型或向真实项目发送测试要求。

提交后的继续复查补充：

| 发现的问题 | 修复与回归证据 |
| --- | --- |
| 扫描遇到业务自己的 `state.json` 后遗漏下层任务 | 通过运行记录特有文件识别任务，业务状态文件不会截断扫描；嵌套任务发现测试通过 |
| 损坏的补充要求回执令正常任务变为未知且无法停止 | 单独校验回执并显示错误，保留真实运行状态及暂停/停止操作；回执故障不会取消执行器调用，持锁运行任务和真实子进程测试均通过 |
| 不规范的结构化输出使观察器抛错，影响子进程执行 | 无效事件被忽略，后续有效输出仍正常展示；真实本地子进程正常退出测试通过 |
| 超长结构化记录被截断后，其尾部被误当普通输出 | 丢弃超长记录直到行结束，下一条公开进度继续显示；跨块大记录测试通过 |
| 旧检查点缺少后来新增的默认隔离字段而被 Web 拒绝恢复 | 与监督器采用相同的默认字段兼容规则；旧配置恢复测试通过 |
| 慢提交返回时覆盖另一个任务的弹窗或新草稿，自动刷新可能重新启用重复提交 | 按任务隔离正在提交的请求，仅更新匹配任务和未改变的草稿；浏览器延迟响应测试验证跨任务隔离、同任务草稿保留及重复请求抑制 |

生效边界：

- “实时”为页面可见时每 3 秒更新，结果来自执行器实际发布的记录；尚无输出时显示等待和上次输出时间。
- 全部任务范围是控制台已登记任务及扫描根目录中发现的运行记录。自定义目录通过 `--runs-dir` 加入；达到扫描限制时页面提示，详见 README。
- 补充要求在下一次 AI 调用时发送，不会改写已经发出的调用。可同时请求当前轮次结束后暂停，再确认方向并恢复。
- 升级前已经运行的监督器需要停止后恢复才能读取新要求，页面明确显示这一状态；保存成功不会显示为已发送。
- “已返回结果”表示包含要求的轮次返回了有效结论，仍需结合实际输出及独立审核判断完成质量。
