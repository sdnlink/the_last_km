# 开发控制台

独立的 `console/` 目录包含 Python HTTP 服务和原生 HTML/CSS/JavaScript 页面，无第三方运行时依赖，无需安装 Node.js 或构建前端。支持 Linux、Python 3.11+。

在仓库根目录启动：

```bash
./start.sh
```

根目录脚本会自动切换到仓库目录，优先使用 `.venv/bin/python`，否则使用 `python3`。可透传全部控制台参数，例如 `./start.sh --port 9000 --cwd /path/to/project`；也可直接执行 `python3 -m console`。

打开 **http://127.0.0.1:8765**。安装本项目后也可执行 `auto-moniter-console`。

## 使用

首次打开概览会进入初始化页面 `/setup`，可选择安装 Codex、Grok、Claude Code、Antigravity CLI、Gemini CLI、Copilot CLI、Hermes、Kimi、CodeBuddy，以及通过 Claude Code 接入的 GLM、DeepSeek。已安装的 CLI 可直接复用；之后通过左侧“Agent 管理”调整模型、服务地址、认证和可执行文件位置。具体安装方式与角色支持见 [Agent 安装与配置](AGENT_SETUP.md)。

任务列表、运行任务概况、跟进任务选择、工作流、交互结论、Git 记录、验收与审计列表及补充要求历史默认根据浏览器可用高度、条目高度和列数自动调整每页数量，无需选择“自动适应”；也可手动指定 10、20、50 条。分页提供上一页、下一页、首末页和跳转页码，定时同步保留当前页，搜索或筛选后回到第一页。交互结论按轮次计数。

分页数量只在页面首次加载时按当前空间计算，初始内容渲染后测量一次条目高度，之后保持该数量。缩放或调整窗口后刷新页面即可重新适配；定时同步、翻页和筛选不会重复检查页面尺寸，也不监听缩放或窗口变化。固定选择的 10、20、50 条按所选数量分页。

所有弹窗支持点击外部关闭，也可使用关闭按钮或 Esc；点击弹窗内部或从内部拖动到外部不会关闭。

- **工作概览**：显示任务统计、主机资源以及全部运行和暂停任务的摘要，每 3 秒更新。卡片展示当前阶段、工作摘要和三类角色状态，可进入实时跟进或完整任务详情。
- **补充要求 / 调整方向**：在任务卡片、实时进展或详情页提交新要求，查看历史内容及执行器、审查器各自的发送/返回回执。输入草稿不会被自动刷新覆盖。可以同时请求在当前轮次结束后暂停，确认结果后再恢复。
- **实时进展**：用于持续跟进一个明确任务。先从左侧选择任务，或从概览/详情点击“实时跟进”；右侧显示所选任务的当前轮次、正在执行的角色、工作流和最近执行/审查结论。默认仅显示当前轮次，可切换最近活动及 worker/reviewer/watcher。暂停或停止任务明确显示正在查看历史记录，可调整方向后恢复执行。完整需求、历轮结论和 Git 记录进入任务详情查看。未选择任务时只加载任务摘要，不拉取工作流。
- **开发任务**：使用表格列出全部任务，逐项展示运行、暂停、停止等状态、执行器、模块进度、时长和资源；可按运行/暂停/停止等状态筛选和搜索。点击任务名称或整行进入任务工作详情。
- **任务工作详情**：`/tasks/<任务编号>` 是任务入口页，在“任务工作详情”标题右侧展示四个入口，下方保留角色状态和实时工作流。点击“交互结论”“Git 追溯”“需求与验收信息”“执行日志 · 原始输出”，分别进入 `/conclusions`、`/git`、`/requirements`、`/logs` 独立页面。每页有自己的标题，只展示对应内容，提供“返回任务详情”，支持直接打开、刷新与浏览器返回。交互结论按轮次倒序归组，点击轮次查看 worker 和 reviewer 的结论、缺口、下一步、验证依据及 watcher 处理结果；缺少角色记录时显示暂无结论，自动更新保留已展开的组。旧 `#/tasks/<任务编号>` 书签会跳转至任务入口页。
- **新建任务**：填写项目绝对路径、需求、执行器和审查器，可指定模型、验收命令、审核频率、时长预算、调用上限和轮次上限。审核频率默认每 5 轮，设为 1 可逐轮审核正常工作结果，设为 0 关闭按轮次审核，仍审核完成候选和阻塞；质量策略的时间或文件数检查点也可提前触发。默认预算 120 分钟、100 次调用，预算上限设为 0 表示不限。关闭“创建后立即启动”可保存为待启动任务。
- **任务操作**：任务列表、实时进展和任务详情均提供“暂停执行 / 恢复执行”。暂停在当前轮次结束后生效，重试等待期间可立即暂停，等待期间显示“暂停中”，可点击“取消暂停”；已暂停的任务继续原会话执行，已停止或中断的任务从检查点恢复。停止会中断执行并保存状态。
- **删除任务**：待启动、已取消、已停止或已结束任务提供“删除任务”按钮，确认后从本控制台移除，刷新或重启后不会被历史扫描重新加入。同步删除该任务运行目录中的 `.log`、`.jsonl`（含轮换文件）、轮次输出文本和提示词。项目文件、Git 历史及任务配置/检查点保留。清理失败时任务保持可见，可重试删除；不跟随符号链接，也不清理项目根目录。运行中、启动中、暂停中、状态未知或回收未确认的任务不能删除；先停止并处理残留进程。删除后的任务编号不能再查询或恢复；其他控制台实例的登记不受影响。
- **恢复已有 CLI 任务**：自动读取运行目录的 `launch.json`，核对项目路径、执行器、审查器、模式及隔离设置，按原模型与预算恢复；模块、需求和验收命令沿用检查点。恢复后仍使用原运行目录和任务编号，控制台重启也可继续管理。缺少原始启动配置或配置不匹配时，页面显示具体原因。已交付、失败终态及被取消的任务不能当作可恢复检查点启动。
- **执行日志**：通过任务详情的“执行日志 · 原始输出”菜单进入后加载，选择工人、审查员或监督器日志，每页行数默认随页面空间和缩放调整，可按页查看整个保留文件；“跟随输出”显示最新一页，手动翻页会关闭跟随。每页响应最多 64 KiB，超长行标明截断。其他详情子页面不请求原始日志。
- **项目 Git 追溯**：新 review-first 任务通过独立审核及固定检查后，代码提交到任务绑定的业务分支，审计结论保存在 `refs/auto-moniter/<运行标识>`。任务详情页显示分支、结论目录、近期提交号、变更文件及可复制的 diff 命令；每次 reviewer 结论关联其核对的 worker 提交。更早轮次通过目标项目中的 `git log` / `git show` 查询，独立于控制台日志保留窗口。
- **自动衔接新提交**：同一业务分支向前更新后，任务在轮次边界识别当前提交，保留已有代码和未完成需求、模块、AUD 问题，开启新会话重新验证。旧版本的完成、审核和验收结果失效；累计预算继续计算。Git 追溯页显示最近 20 次衔接记录。已因旧版本保护停止的可恢复任务也可直接点击恢复。新提交中已落盘且工作区一致的测试/CI 文件成为新的保护基线，未提交的保护文件改动仍需修复；分支切换、历史重写或合并冲突会显示具体原因。
- **资源监控**：查看真实主机 CPU、内存、磁盘和最近 60 次浏览器采样的趋势。任务资源统计本地进程树的 CPU 和 RSS 合计；CPU 以单核心为 100%，多核心任务可超过 100%。Paseo daemon 及远端进程不计入任务占用。第一次采样尚无 CPU 时间差，显示“采样中”。

实际执行通过独立进程调用 `python -m auto_moniter run --guard`，保留原有监督、工作区锁、模块验收、预算和独立审查机制。执行前需要安装所选 agent CLI 并完成登录；页面检测到命令存在不代表已登录。同一个项目同时执行多个任务会被拒绝，待启动任务需要手动启动，不会自动排队领取。

Web 新建任务使用 `--git-history required`，目标目录须属于 Git 仓库，无法保存 Git 轮次记录时会停止执行。普通目录请先在目标目录执行 `git init`。恢复已有 CLI 任务沿用其原参数；旧版未指定 Git 参数的任务按 `auto` 模式恢复，在 Git 项目中开启后续轮次留痕。

reviewer 按轮次与 worker 串行运行。详情卡片显示最近审核轮次、实际审核频率、间隔计数和等待原因；worker 超时或被停止后会先处理失败，等待后续 worker 正常返回才再次送审。运行中的任务仍使用保存的原配置，新建任务表单不会改变既有运行的频率。Web 与 README 中全部配置的覆盖差异见 [配置核对清单](CONFIGURATION_AUDIT.md)。

新启动的监督器在执行过程中持续写入有大小上限的 `live.jsonl`，无需等待整轮结束。对于升级前已经运行的原生 Codex 任务，控制台会按项目目录、轮次开始时间或已保存的会话编号精确匹配本地会话，仅读取公开进度消息和工具活动；匹配不唯一时保留监督事件，不猜测归属。读取会话遵循 `CODEX_HOME`。尚未输出消息或工具活动的后端会显示等待输出，已有模块通过数不代表当前正在编辑哪个模块。

补充要求保存为当前运行目录的 `directions.json`，由新版监督器在下一轮调用前加入执行器和审查器的提示词。已经开始的模型调用不会中途改写。仅在本地进程实际启动后登记“已发送”，该轮返回有效结论后登记“已返回结果”；这表示有结果可查，不代表 AI 已正确满足要求，仍需核对实际输出和独立审核。后续轮次继续收到完整补充记录。新要求在审核或交付期间到达时，监督器会要求工人继续处理；任务已最终结束时提交会明确拒绝。

升级前已运行的监督器会在弹窗中标明需要停止后恢复，防止把只保存的要求误报为已交给 AI。停止或待启动任务的要求会在启动后发送；已交付、已取消或失败终态应创建后续任务。补充记录每项最多 4000 字、每任务最多 64 项且总量不超过 128 KiB，达到上限明确提示，不静默淘汰未处理要求。

## 配置

页面内容、脚本、样式和数据按当前访问页面加载。离开页面时取消该页面的在途请求并停止其轮询；后台标签页暂停数据请求。新建任务、补充要求和停止确认窗口在首次点击时才加载各自表单；执行日志只在日志子页面请求。

每条已留痕结论提供“查看本地提交”，展示审计引用、当前检出分支、提交号、时间、Git 中的结论和核对命令。记录保存在目标项目的 `refs/auto-moniter/<运行标识>`，可用 `git log <该引用>` 查看。业务提交号在任务详情中单独显示，旧任务不会被误标为已发布代码。弹窗及 `/api/tasks/<编号>/git/<提交号>` 仅在点击时加载，读取实际 Git 对象。审核结论另显示 watcher 是否接受关闭，拒绝时保留 reviewer 原文和系统原因；审计问题是否解决以 watcher 清单为准。

| 页面 | 地址 | 自动更新的数据 |
| --- | --- | --- |
| 初始化 / Agent 管理 | `/setup` | `/api/agents/setup`：CLI 检测与安装进度，保留未保存的表单输入 |
| 工作概览 | `/overview` 或 `/` | `/api/overview`：统计、运行任务摘要与主机资源 |
| 开发任务 | `/tasks` | `/api/tasks`：任务列表摘要 |
| 实时进展 | `/progress?task=<编号>` | 任务列表摘要及所选任务的 `/api/tasks/<编号>/progress` |
| 任务详情 | `/tasks/<编号>` 及其 `/conclusions`、`/git`、`/requirements`、`/logs` 子页面 | 仅 `/api/tasks/<编号>`；日志子页面额外请求该任务日志 |
| 资源监控 | `/resources` | 仅 `/api/resources`：主机与任务资源 |

原始日志 API 支持 `page`（默认 1，0 表示最新一页）和 `page_size`（默认 10，范围 1–100），返回总行数、页数、当前页及行号；文件追加时增量更新行索引，文件轮换或缩短后重建。分页只展示仍保留的运行记录。

概览、列表及资源接口不返回完整需求、方向补充、工作流或 Git 历史，也不读取执行器会话。各页面的 HTML/JS/CSS 位于 `static/pages/`，共用导航外壳和基础组件。

```bash
python3 -m console --port 8765 --cwd /path/to/project
python3 -m console --data-dir /path/to/console-data
python3 -m console --runs-dir /path/to/custom/runs --runs-dir /other/runs
```

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `--port` | `8765` | 监听端口 |
| `--cwd` | 当前目录 | 新建任务默认目录、项目内记录发现根目录 |
| `--data-dir` | `<cwd>/.auto-moniter/console` | 任务定义、运行记录与控制台单实例锁 |
| `--runs-dir` | 无，可重复 | 额外发现已有任务的运行目录 |

自动扫描 `$AUTO_MONITER_STATE_DIR`（或原有默认状态目录）和 `<cwd>/.auto-moniter/`，以及显式指定的根目录，最多向下扫描 5 层，每个根目录最多访问 2000 个目录，不跟随目录软链接。历史记录不复制。自定义层级更深时，将 `--runs-dir` 指向更接近运行记录的位置。

任务定义保存在 `tasks/<id>.json`，新任务运行记录在 `runs/<id>/`。运行记录与定义会持久化；控制台重启后重新识别仍在执行的任务。关闭控制台后任务继续执行，重新启动控制台可再次查看和控制。

控制台仅监听 `127.0.0.1`，使用 Host/Origin 校验及会话令牌保护写入接口。远程查看可使用 SSH 本地转发：

```bash
ssh -L 8765:127.0.0.1:8765 user@server
```

## 2026-11-08 运行闭环补齐

新建任务现在支持固定模块 JSON、strict 审核/worker 隔离、保护路径、单轮/空闲/验收超时和日志/历史/模型会话容量限制。审核默认 strict；不支持该边界的后端组合会拒绝创建或启动。Web 默认选择独立命令验收，至少填写一条命令；只有明确选择“仅双方审核”才允许不配置命令。固定模块清单可在高级配置中输入，例如：

```json
[{"id":"API","title":"接口交付","acceptance":["正负路径均通过"],"depends_on":[],"checks":["python -m unittest discover -s tests"]}]
```

恢复操作先打开预算窗口，可明确追加时间和调用轮次；累计用量保留，已耗尽预算且未追加时拒绝启动。同一工作树及父子目录任务相互排斥；独立 linked worktree 可分别运行。

默认运行目录预算 64 MiB，Git 对象及审计历史 512 MiB，已知模型会话目录合计 4 GiB，保留最近 50 轮。容量为定期采样停止条件，可能暂时超出阈值；共享目录统计包含既有数据和其他任务，不自动删除。Paseo/第三方存储仍需部署配额。完整接线与剩余 CLI 专属项见 [配置核对](CONFIGURATION_AUDIT.md)。历史任务保持原隔离和预算配置。

质量策略入口位于新建任务的高级配置，预填保护测试、验证进展、600 秒工作检查点、20 个文件的提前审核和 3 次重复阻塞停止。可填入 `requirements` 将需求条目关联固定模块与实际文件证据，模块可用 `files` 声明影响范围。详情页展示上次需求覆盖结果，watcher 卡展示后端报告用量；这不代表未报告的费用为零。完整配置与 files_only 审核能力边界见 [质量策略](../QUALITY_POLICY.md)。

## 引导式验收

“完成标准与检查方案”现在位于新建任务的基础区域。先选任务类型并填写文字标准，再扫描并勾选已有检查；可点击“检查运行前提”查看解释器或依赖缺失。命令详情和手填命令仍在高级区域。没有检查可选时，可以明确创建仅制定验收方案的任务或仅语义审核任务；不会静默降低验收模式。

检查目的、耗时、副作用和未知覆盖均有说明。任务详情展示选定方案及上次实际检查结果，原始日志增加验收检查日志入口。完整流程及 NDR 文档历史证据处理见 [引导式验收说明](../ACCEPTANCE_GUIDE.md)。

新任务默认流程已改为 reviewer 需求完善 → watcher 固化 → worker 实现 → reviewer 审核 → watcher 验收及本地提交。详情增加需求完善结果，工作流显示需求完善阶段；审批前没有本地提交时明确显示待审状态。旧任务恢复仍保留 legacy 原流程。Grok 认证失败会在任务提示中给出登录/服务环境处理方法，不再循环重试。详见 [工作流程](../WORKFLOW.md)。
