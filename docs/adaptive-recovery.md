# 自动恢复与项目经验

系统按“观察失败 → 审核纠错 → 实施修复 → 独立复核 → Watcher 验收 → 保存经验”推进。用户给出目标后，普通计划错误和已定位的实现缺陷由系统处理，恢复不新建任务、不重置累计预算。

## 已实现的闭环

1. 需求 Reviewer 返回可解析的计划，但计划存在多个不同校验错误时，Watcher 保留研究结果，逐次反馈具体错误，在同一运行中继续只读纠错。最多修正 4 个不同错误；同一错误连续重现不再继续重放。纠错次数和原因保存为 `adaptive-recovery.json`，重启不能重置这一限制。输入版本、派单和用户补充要求变化后使用新恢复上下文。
2. Reviewer 对一个已被 Watcher 日志中的真实断言/测试失败证据判失败的候选仍给出 accepted 时，Watcher 要求只读重评，提供当前日志与检查回执。Reviewer 确认可修复缺陷后返回 changes_required，Worker 在原授权范围修复，Watcher 重跑检查并重新独立审核。仅覆盖完整、源码未变化、回执有效且有实际断言/测试失败输出的检查；单独 exit 1、缺工具、停止、超预算或证据遭替换不会冒充产品缺陷交给 Worker 盲改。
3. Watcher 记录派单的真实检查失败。后续同一运行、同一任务的检查通过只构成待确认的修复；直到独立审核、固定门禁及发布路径通过并接受派单，才增加已验证经验计数，并保存 Reviewer 的修复说明与依据。失败、测试单独通过或另一个任务的通过都不会提升为成功经验。
4. 项目经验位于外部私有状态目录的项目空间 `experience.json`，最多保留 64 个模式。后续同一项目的模型调用自动读取相关已验证经验；Worker 仅获得与当前目标相关的经验，Reviewer 可查看项目经验。每次最多注入 4 项。经验是历史上下文，不是当前成功证明或新的执行权限，原有验收仍全部执行。

读取经验不调用模型，也不创建目录：

```sh
auto-moniter experience --cwd /path/to/project
```

输出包含观察到的失败模式、已验证修复次数及各目标的统计；没有历史经验时返回零值。经验读写失败只记录延期，不影响已获授权任务正常执行。损坏经验文件保留，不覆盖为“空历史”。

## 一并修复的问题

- 计划最多可有 200 个任务，但单项依赖原先被隐式限制为 20，最终模块验证引用更多已接受任务时会被错误拒绝。现在依赖容量与计划一致，schema 与运行时统一，仍校验 ID、去重、既有依赖和完整计划顺序。
- `scope_repair` 本来是 Watcher 自己保存的重新规划字段，但恢复校验只接受两个旧字段，导致合法检查点被拒绝。恢复现在兼容该布尔字段并保留其校验。

## 当前能力边界

这是执行策略、计划纠错和可验证项目经验的持续改进机制，不会训练底层模型权重，也不会在后台任意改写正在运行的监督器代码。修改系统源码仍采用正常的 Worker 实施、Reviewer 独立审核和 Watcher 测试发布流程。模型服务认证、外部权限、真实不可用平台、用户停止及既定预算仍是实际约束，不能用循环重启或虚报完成来消除。

系统自身代码的隔离修改、独立审核、全量验收、源分支更新及控制台启用/失败回退由 [自动进化流程](self-evolution.md) 提供；正在执行的独立监督进程不会被热替换。跨项目自动迁移经验、自动更换模型供应商，以及为所有外部故障提供长期等待调度仍未实现。持续运行不等于无限重放：耗尽纠错机会时保留候选、错误和恢复记录，明确说明为何停止。
