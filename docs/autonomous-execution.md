# 开发任务的自主推进与真正阻塞

普通开发指令授权在原范围内进行可逆的实现、局部修复和相关测试。Reviewer可以选择合理默认方案并记录假设，不应要求用户决定每个实现细节。Reviewer的只读限制只约束审核轮次，不表示后续Worker也不能写代码。

需求审核第一次返回`needs_input`时，Watcher保存原分析和原始输出，在原预算内再进行一次只读复核：能否先派发不依赖该问题的具体增量？可独立工作时应给出合法派单，并在约束中保留尚未完成的最终条件；没有可独立工作的步骤时，仍返回具体问题并保持`action_required`。这不会把阻塞状态强制改为批准，也不会启动未经审核的实现。复核最多一次，不无限轮询同一个问题；停止请求、预算和工作区变化检查继续生效。

不得把缺少编译器、公开资料偶发不可访问、稍后的外部发布或格式检查无法验证功能，一概提升为所有实现的前置条件。可以先做的工作继续，缺失证据如实记录，不声称测试通过。缺少不可替代的环境/凭据、未授权的外部操作或真正影响后续全部工作的业务决定仍会停下来。用户明确要求的最终验收标准不能被自动降低，例如不能擅自把“获得Apple正式审核结果”改成“源码编译通过”；但没有获得审核结果也不必阻止独立的源码开发。

## 原生Swift检查

Reviewer可在`test_files`声明与现有工程关联的Swift测试文件，并引用`auto:N`，不需要用户手工输入可执行命令或新增检查ID。Watcher支持：

- 现有`Package.swift`下的测试，运行真实`swift test`。
- 现有共享Xcode scheme中的XCTest目标，按声明文件内的XCTestCase类运行原生测试。多个scheme匹配时不猜测；跳过的Testable不会被采用。

Swift测试文件也纳入已有测试保护规则。命令由Watcher从受约束的文件路径和工程元数据生成，不接受模型提供任意shell命令。缺少Swift/macOS/Xcode/iPhone模拟器时明确失败；原生编译、源码匹配、零测试、全部跳过不能冒充行为通过。XCTest使用无需Apple开发者证书的模拟器ad hoc签名，以保留真实Keychain测试。完整交付仍需要所有固定检查和已接受回归，不能用新增入口绕过必要环境。

## 评审报告矛盾与评审期间的新要求

2026-11-16同一任务再次在0个Worker轮次后停止，原始错误是`Ready elaboration needs acceptance criteria and no unresolved blockers`。评审报告已经给出19项具体函数计划及可独立执行的首项，但同时返回`status=ready`和非空`blockers`。这些字段中的文字描述的实际是后续原生环境及最终验收条件，不阻塞当前内容校验增量；程序此前直接将字段矛盾变成了人工处理状态。

现在这种字段类型完整、但状态与内容冲突的报告会先只读退回Reviewer修复一次。`ready`的`blockers`必须为空；后续尚未完成的验证或外部条件写入`constraints`，不能删除或冒称已完成；真正阻塞当前增量时返回`needs_input`。Watcher不自动清空模型的阻塞，不自行批准任务，重复矛盾或预算/停止条件仍会阻止派工。旧报告与修复调用原文均保留。

用户在长时间需求评审过程中追加要求时，旧轮输出不直接批准或派工。先检查只读工作区、进程失败与停止条件，再保存尚未批准的分析，保留旧轮日志，并使用最新用户版本重新审核。最新决定只影响后续合法审核，不把旧报告改成已消费该指令。持续变更仍受原调用和时间预算限制。

恢复时优先复用最新被拒报告中的分析与函数计划，避免旧缓存覆盖已经完成的调研。上下文缓存允许保存字段完整但状态矛盾的原文，只为修复提供上下文；正式接受仍执行严格校验，缓存不提供实现授权。本任务中“按源码与功能验收，Apple审核作为外部结果”的确认已保存为用户版本3，恢复将送入新一轮审核，不再沿用版本2中尚待确认的表述。

## 原子文件清单与重复范围故障恢复

后续实际运行暴露了更深的范围矛盾：首项路线开发需要资源、PBX引用、辅助代码及文档，旧派单却只允许单函数和测试。14轮中13轮候选未变化，仍反复等待相同门禁，最终触发无验证进展保护。

派单新增`edit_files`，列出一个原子增量确需修改的精确文件；列出的源码允许整文件相关修改，未列出时继续执行单函数保护。字段不能包含目录、通配符、符号链接、既有测试或测试配置，也不能扩大用户的并行文件范围。资源和辅助文件指纹纳入已验收记录，后续改动使旧覆盖失效；纯验证和预批准集成不能借该字段扩权。

连续两次相同候选被范围拒绝后，监督器仅尝试一次只读规划修正，保留主函数、ID、检查和验收条目。成功后复用原候选，重新检查与独立审核；修正无效时给出具体范围错误，不继续第三次相同Worker提交。不重置原基线、预算、审计事项或实际检查结果。
