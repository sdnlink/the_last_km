# 离线 CI 与开发机环境差异

日志中的 403/404、预算耗尽和轮数耗尽可能是测试主动构造的负向场景。是否通过以 unittest 的最终结果及断言为准，不把这些请求日志单独当作线上故障。

本次复现确认：角色切换测试使用真实 Codex/Grok/Claude 适配器创建已停止的检查点，但没有提供离线可执行文件；开发机恰好安装了 CLI，因此未暴露问题。CI 缺少 CLI，真实启动预检返回 `invalid`，随后检查点及恢复断言失败。历史容量配额测试也使用真实 Codex，导致测试配额前先因缺少 CLI 而返回 `invalid`。

修复保留生产启动预检。角色测试为适配器提供测试目录内的可执行替身，仅用于验证身份、权限、角色授权和检查点；一旦意外执行则退出 97，不连接模型。容量测试使用空脚本 provider，并增加未发生任何调用的断言。真实执行器不存在时仍应拒绝启动，既有发布测试继续验证这一行为。

CI 明确安装 Node 22，因为 Python 回归包含实际 Node 前端测试。Python 3.11/3.12 矩阵各自创建只包含该版本 Python、Node 及系统工具的测试 PATH，不暴露开发机或 runner 其他路径中的模型 CLI；忽略用户/系统 Git 配置。原有 wheel 构建和离开源码目录安装后的 doctor/selftest 保留，新增独立 Node 测试入口，并将 console 纳入编译检查。

本机准确复现时须让测试子进程也使用受支持的 Python。仅将 PATH 改成 `/usr/bin:/bin` 不够：本机 `/usr/bin/python3` 是 Python 3.7，而项目要求至少 3.11，会引入与本次 CI 无关的解释器故障。因此复现使用独立工具目录中的 Python 3.12 和 Node 22 符号链接。

修复前相同隔离环境复现角色与配额相关 7 项失败；修复后角色、配额及发布针对性检查 26 项通过。原用户日志未包含所有失败的完整堆栈，不能仅凭所示摘要逐项归因；完整离线回归用于验证当前版本。

最终验证：无模型 CLI、无全局 Git 配置的 Python 3.12 / Node 22 环境，`python -m unittest discover -q` 共 617 项全部通过（131.166 秒）；三份 Node 测试通过，编译与 `git diff --check` 通过。wheel 离线构建成功，并在 `/tmp` 下的独立虚拟环境安装；离开源码目录后的版本、doctor 和四次离线 worker/reviewer 调用 selftest 均通过。GitHub Actions 的 Python 3.11 矩阵尚需远程运行确认，本次没有推送或触发远程 CI。
