# 可选裁判与异常恢复

裁判是 Worker、Reviewer 之上的异常调度角色。创建任务时勾选“启用裁判”，可从当前 Reviewer 执行器的模型目录单独选择裁判模型，也可填写有效模型 ID。留空使用 Reviewer 模型；即使模型相同，也创建独立只读会话。恢复窗口可以启用、关闭裁判或选择模型。默认关闭，旧任务不会自动启用。

命令行新任务在原有 `run` 参数上添加 `--referee --referee-model MODEL`。已有任务在原有恢复命令上添加这两个参数；`--no-referee` 关闭。模型必须是当前 Reviewer 执行器支持的模型，沿用其认证、参数及隔离配置。

## 介入条件

- Worker 连续两次执行失败，或发生单轮超时、输入等待、持续网络重连中断。
- 同一候选的 Reviewer 传输或结论失败，已有一次 Reviewer 自我纠错仍未恢复。
- 连续无进展达到 `restart_after_stall` 阈值（关闭普通会话重启时裁判采用 3 轮），或触及质量策略的无进展阈值。
- 原规划纠错已用尽，或候选验收流程受阻。

正常实施、正常审核和正常交付不调用裁判。启用裁判且未设置单轮超时时，模型单轮最长 1800 秒，防止持续输出的调用一直占用任务；显式单轮上限优先。裁判诊断最长 180 秒、无输出等待最长 60 秒。Paseo 守护会话也受相同单轮上限约束。

## 决策与执行

裁判读取原需求、当前需求版本、完整计划、已接受派单、模块、审计项、近期调用/检查证据及原累计预算，返回以下一种决策。

| 决策 | 后续执行 |
| --- | --- |
| `retry_worker` | 保留当前文件，以新会话按裁判诊断继续当前派单。审核传输故障不能使用这一决定重新实施已提交候选。 |
| `retry_reviewer` | 复用完整 Worker 候选继续独立审核。真实行为断言失败时不得反复请求批准，须安排修复或重排。 |
| `replan` | Reviewer 根据裁判指令重新安排剩余工作。可以替换阻塞的派单或插入修复，已开始的替代派单须使用新 ID。原候选保留，已接受工作不重新开发；完整计划的验收覆盖、依赖与检查校验继续执行。 |
| `wait` | 记录不可替代的外部前提，保留现场并以 `action_required` 结束。 |

裁判的调度指令优先于相冲突的 Worker/Reviewer 建议，但不能修改原需求、删减原验收项、重写已接受任务、关闭 AUD、改写固定检查、增加预算、绕过权限或忽略显式停止/暂停。裁判不直接开发、测试、提交或判定最终交付。所有候选仍需固定检查及独立审核。外部认证、必要权限和工具不可用时，它不能保证任务最终完成；运行会保留实际阻塞原因。

## 持久记录与界面

决策写入 `referee-decisions.json`，单次诊断提示词、原文及日志保存为 `920001-referee-*` 等文件。控制台显示裁判角色及“裁判介入中”阶段，执行日志可以查看完整诊断和决策。当前决策、开关与模型随 `state.json` 和最终报告保存，恢复不重置累计用量。

同一源码、派单、需求版本、执行器和检查组合最多介入 3 次，一次运行最多 12 次。中断、失败、已捕获但未确认应用的裁判调用也有持久记录，重启不会盲目再发同一诊断。用尽恢复次数会明确报告 `action_required`。裁判输入发生变化、只读过程中改写源码、输出格式无效或决策违反执行条件时，拒绝应用并保留记录。
