# 爬楼梯任务反复停工：执行系统复核

复核日期：2026-11-16。对象是 Auto Moniter 及其对任务 `5aede73944484c89b448a0d85ef275fc` 的实际执行，而不是把已准备的路线内容认定为完整 iOS 产品。

## 结论与需求归因

当前反复停工的主要原因是 Auto Moniter 的派工范围表达和失败恢复设计。用户早期的“不会被 App Store 拒收为止”不能由本地源码或测试保证；但用户版本3已明确改为源码、功能和真实验证验收，所有者确认丰富程度，Apple 审核作为外部结果。因此，本次反复循环不能再归因于该旧表述。

“丰富差异化”仍有主观最终验收部分，需要具体增量、可执行验证与所有者验收。但它不妨碍先交付已获授权的独立功能，也不要求用户修正监督器的文件权限模型。

## P0：规划范围与可执行权限不一致

位置：`auto_moniter/function_tasks.py` 的派单结构，`auto_moniter/function_gate.py` 的 `scope_problems`，以及 `Supervisor._function_planning_contract`。

第一项 `V3A01` 要求交付路线内容、资源绑定、真实结构校验和说明文档。实际改动是五个文件：

- `scripts/check_ios_project.py`
- `scripts/tests/test_journey_catalog.py`
- `ios/StairClimb/Resources/ClimbJourneys.json`
- `ios/StairClimb.xcodeproj/project.pbxproj`
- `docs/DIFFERENTIATION.md`

计划在文字边界里允许这些改动，旧的机器结构却只能表达一个主函数和新增测试。范围门禁直接拒绝后三个文件，必需检查尚未运行就写入 `checks=[]`、`complete=false`。单函数外的辅助声明也存在同类结构限制。这不是要求用户重新描述产品能解决的问题。

修复增加 `edit_files`：Reviewer必须在结构化派单中列出一个增量真正需要的精确文件。列出的源码文件允许辅助声明、导入、属性及相关函数的一体修改；未列出的文件及默认的严格函数范围继续受保护。文字边界不再被当作可执行权限。路径不得越界、使用通配符或符号链接，不能借此修改现有测试或测试配置，也不能扩大用户声明的并行任务范围。纯验证派单及预批准集成派单不能通过该字段扩权。

整文件清单由独立Reviewer规划，在派工前校验；它不是根据Worker已经写了什么自动放行。接受后保存清单文件的内容/权限指纹，后续资源或辅助文件变化会使对应旧验收覆盖失效。

## P1：监督流程缺陷被反复交给Worker

位置：`Supervisor._prepare_candidate_checks`、主循环及停滞恢复。

运行记录显示14轮Worker、32次模型调用、0项派单验收。第2至14轮共13轮的候选指纹相同，均为 `8107be74f1bad1bf38a11dce3bd04fe40c80b09e4e80750bc7deaad9d28f1e1c`。Reviewer多次说明源码已无修复项，`AUD-4`是范围门禁/检查记录问题，仍被送回Worker重复确认，最终到达12次无验证进展限制。

保留无进展保护是必要的，问题是缺少正确的恢复路径。现在两个相同候选连续遇到相同类型的范围拒绝后，先退回只读规划；允许修正同一未完成任务的文件清单，但必须保留任务ID、主函数、依赖、验收条目、测试路径和检查编号。规划和候选都有效时，复用原Worker候选，重新运行真实Watcher检查并独立审核，不制造第三次无变化的实现轮次。修复后仍拒绝则明确报告范围修复失败，不继续消耗相同循环。修复不重置原始工作区基线、不关闭旧审计问题，也不伪造检查通过记录。

## P1：当前执行环境不具备iOS原生验收能力

本机实际检测不到 `swift`、`xcodebuild`、`xcrun` 或 `gh`。下一项Swift派单 `V3P01` 声明 `GoalRulesTests.swift`，需要原生执行器。因此，消除范围冲突以后，现有主机仍不能完成整套iOS原生验收。需要接通macOS/Xcode执行通道，例如项目已有GitHub工作流所使用的macOS runner；工作流源码存在不代表Auto Moniter已经具备触发、获取对应候选测试结果和校验其提交号的能力。

检查时当前任务原预算7200秒，累计使用6675.352秒，仅余约525秒。这是任务配置的实际限制。修复不能靠偷偷重置预算、把未运行的Swift测试算通过，或者声称Python结构检查证明了iOS交互效果来实现“持续执行”。

这两项是后续交付条件，应与业务决策、源码缺陷和监督器故障分别报告。当前补丁解决文件范围冲突及其重复循环，不宣称已经实现远程macOS执行或完整iOS产品。
